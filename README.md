# 跨国临床试验中央随机登记与揭盲控制台

研究中心离线入组后，入组、待提交队列与安全审计统一接入**可恢复的中央登记流程**：
随机号与治疗组只由中央账本发放，确认以中央回执为准，断网保留原入组内容并按原提交顺序重放。

## 技术栈

Nuxt 3、TypeScript、Element Plus、Pinia、Nuxt 路由、Axios、VueUse、VeeValidate、Zod、Vue I18n。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：`62028`

## 核心流程与不变量

- **中央唯一登记**：`server/centralRegistry.ts` 是唯一发号方。受试者编号与身份核验标识全场只能登记一次，
  冲突由中央拒绝（`duplicate-conflict`），冲突不占号。
- **确认以中央回执为准**：登记成功签发带有效期的中央回执；页面受试者列表、待提交队列、安全审计引用同一份回执号。
  - 重复确认幂等：同一入组请求（requestId）并发或反复确认，只真正入库一次，永远返回首次入库的同一随机号/治疗组。
  - 多管理员并发：入口瞬时锁 + 中央串行队列 + 浏览器 Web Locks（跨标签页互斥），进入临界区前重读账本。
  - 过期回执、未知（伪造）回执不能改写已落定分组，只能“刷新回执”后再确认；随机号/治疗组沿用原中央结果。
- **角色隔离**：
  - 药品管理员：治疗组永远遮蔽，只能维护发药信息（药盒号、批号），不能入组、不能揭盲。
  - 研究者：治疗组默认隐藏；紧急揭盲必须填写原因，审计只追加，已揭盲不可改写。
  - 监察员：仅可见已揭盲记录的治疗组，用于核查。
- **断网可恢复**：离线或中央不可达时，原入组内容（编号、身份标识、中心、分层、提交顺序 orderIndex）原样入队，本地绝不发号；
  恢复后按 orderIndex 升序重放，中央不可达即暂停保序；每条失败记录保留失败原因与重试次数。
- **启动对账**：页面加载时以中央账本重建受试者列表，已入库记录沿用原随机号；队列中中央已落定的项自动补登。
- **安全审计**：所有关键动作（入库、重复拦截、确认失败、回执过期/未知、重放、揭盲、发药、越权拒绝）只追加、不可删除或改写。
