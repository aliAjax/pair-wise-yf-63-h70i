# 跨国临床试验随机分组和揭盲控制台

源提示词摘要：研究中心按分层因素生成随机分组；药品管理员只见发药信息，研究角色正常情况下不可见治疗组；重复受试者和编号冲突被阻止；紧急揭盲需填写原因并形成不可删除审计记录，断网提交进入待处理队列。

## 技术栈

Nuxt 3、TypeScript、Element Plus、Pinia、Nuxt 路由、Axios、VueUse、VeeValidate、Zod、Vue I18n。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：`62028`

## 中央登记流程（核心）

入组、待提交队列与安全审计共用同一次中央入库结果，由模拟中央登记处（`stores/registry.ts`，真实环境对应远端 IWRS/CTMS 服务）兜底：

- **一次登记**：受试者编号与身份核验标识在中央台账中只能登记一次，重复入组（含不同管理员、不同标签页）被拒绝并审计。
- **回执为准**：确认入库以中央回执为准，随机号与治疗组由中央签发；页面、队列、审计展示同一个回执号。
- **幂等重放**：每次提交携带客户端幂等键，同一记录重复确认返回同一份回执，沿用原随机号，不新建分组、不改写已落定治疗组。
- **过期回执拒绝**：回执有有效期，重复或过期回执不能改写已落定分组，并追加审计。
- **失败可恢复**：断网时原样保留入组内容进入队列；联网后按原提交顺序（FIFO）重放，失败记录保留原因与重试次数，可逐条重试或一键重放。
- **角色隔离**：研究者可入组/揭盲（揭盲必填原因）/确认；药品管理员仅维护发药信息（不可见治疗组、不可入组/确认）；监察员只读。
- **多标签页并发**：管理员在不同标签页确认时，通过 `storage` 事件同步同一份中央结果。

## 可用流程

- 入组：机构、分层因素和受试者编号校验后，由中央签发分层区组随机号与治疗组。
- 防重复：相同身份标识、研究中心编号或幂等键都会被中央台账拒绝。
- 角色隔离：研究者、药品管理员和监察员看到不同的分组隐藏规则与操作权限。
- 安全审计：紧急揭盲要求原因，添加后只能追加，不能删除或改写；回执重放、过期、失败均留痕。
- 离线队列：模拟离线提交进入待提交队列，联网后按原顺序重放，失败可重试。
